Схема структуры и работы агентной системы на LangChain/ZeroMQ

Ниже приведена полная схема компонентов проекта, взаимодействий между ними и используемых протоколов обмена данными.

1. Компоненты системы

ActionLLM-Оркестратор (Python сервис)

Подключение к локальной LLM через HuggingFace (transformers или llama.cpp)

Генерация и маршрутизация задач

Хранение метаданных задачи

Обработчик ZeroMQ сообщений

Агенты (Python-классы)

FileAgent: операции с файлами и директориями, UAC-обёртка

ProcessAgent: парсинг и управление процессами

APIAgent: взаимодействие с внешними API

AnalyticsAgent: ИИ-аналитика данных

Каждый агент реализует общий интерфейс:

def handle(task: dict) -> dict

подписка на ZeroMQ топик agent.<name>.tasks

публикация результатов на agent.<name>.results

ZeroMQ Message Bus

XPUB/XSUB или PUB/SUB топологии

Топики:

orchestrator.tasks

orchestrator.results

agent.<name>.tasks

agent.<name>.results

Память (Memory Store)

Redis (in-memory) для краткосрочной истории

SQLite для долговременного хранения контекста

Подключается к каждому агенту и оркестратору через адаптер LangChain Memory API

PersonaLLM-Интерфейс

Чат-сервис (REST или WebSocket)

Хранение сессий, матрёшка памяти

Посылает запросы к ActionLLM для запуска задач и получает результаты

Мониторинг и Логи

Logging Handler: все события ZeroMQ и LLM через LangChain Callbacks сохраняются в JSON-файле

По необходимости запускается Streamlit дашборд для визуализации очередей и статуса агентов

3. Детали обмена данными

Формат сообщений: JSON с полями

task_id — UUID

agent — название агента

params — словарь параметров

result — словарь с результатом обработки

timestamp — ISO-строка времени

ZeroMQ топики:

orchestrator.tasks (PUB)

agent.<name>.tasks (SUB для каждого агента)

agent.<name>.results (PUB от агента)

orchestrator.results (SUB оркестратора)

Память:

Подсистема Memory Adapter (LangChain)

Redis хранит короткий контекст (последние N сообщений)

SQLite накапливает логи диалогов и итоговые ответы

UAC / Права:

Каждый агент при необходимости вызывает обёртку runas

Логика проверки ctypes.windll.shell32.IsUserAnAdmin()
